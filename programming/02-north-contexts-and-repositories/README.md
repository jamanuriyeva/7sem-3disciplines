# Север 02. Контексты и репозитории

Модульный монолит содержит пять ограниченных контекстов: Catalog, Ordering,
Inventory, Payment и Shipping. Каждый контекст владеет своим агрегатом и
предметным языком. Связь между ними выражается ценовыми снимками и
типизированными идентификаторами, а не импортом чужого корня.

Репозиторий возвращает обычный агрегат. SQLAlchemy применяется только к строкам
`…Row` в инфраструктуре; `…DataMapper` переводит между строкой и состоянием
корня. Прикладные службы зависят от малого порта локальной транзакции и
реестра репозиториев, а не от SQLAlchemy. В базе хранится актуальное состояние,
а не поток событий.

Переход от стадии 01 меняет вход команды добавления строки: вместо передачи
цены интерфейс получает опубликованное предложение каталога. В `Order` всё так
же сохраняется собственный снимок цены, поэтому прежняя предметная гарантия
не ослабляется.

```bash
uv run python -m north_marketplace
uv run pytest
uv run uvicorn north_marketplace.api:create_app --factory
```

## Службы

- `CatalogPricingService` создаёт `PriceQuote` из нескольких предложений;
- `WarehouseAllocationService` возвращает `AllocationPlan` без изменения склада;
- `ShipmentPlanningService` возвращает `DispatchPlan` без изменения отправлений.

Каждый результат затем применяется прикладной службой к одному агрегату в
отдельной локальной транзакции.
